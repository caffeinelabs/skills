# Migration: v0.x.y -> v1.x.y

## Summary

v1 updates the `caffeineai-invite-links` mops package to `1.0.0` and moves all required invite-link actor endpoints into `MixinInviteLinks`. Apps no longer declare `generateInviteCode`, `submitRSVP`, `getAllRSVPs`, or `getInviteCodes` manually in `main.mo` or custom mixins. Lint rules now check for `include MixinInviteLinks(accessControlState, inviteState)` instead of per-function declarations in the actor body. Invite state is owned at actor top level via `InviteLinksModule.initState()` and passed into the mixin.

Prerequisite: `caffeineai-authorization ~1.0.0` with `include MixinAuthorization(accessControlState, null)` in `main.mo`.

## Breaking changes

### 1. `mops.toml` version bump

```diff
-caffeineai-invite-links = "0.1.1"
+caffeineai-invite-links = "1.0.0"
```

The package now depends on `caffeineai-authorization` for admin checks inside the mixin.

### 2. Replace manual invite-link endpoints with `MixinInviteLinks`

Remove all hand-written invite-link actor endpoints. Keep invite state at actor top level and pass it into the mixin in `main.mo` (not in a custom mixin file):

```diff
 import AccessControl "mo:caffeineai-authorization/access-control";
 import MixinAuthorization "mo:caffeineai-authorization/MixinAuthorization";
 import InviteLinksModule "mo:caffeineai-invite-links/invite-links-module";
-import Random "mo:core/Random";
-import Runtime "mo:core/Runtime";
+import MixinInviteLinks "mo:caffeineai-invite-links/MixinInviteLinks";

 actor {
     let accessControlState = AccessControl.initState();
     include MixinAuthorization(accessControlState, null);
     let inviteState = InviteLinksModule.initState();
+    include MixinInviteLinks(accessControlState, inviteState);

-    public shared ({ caller }) func generateInviteCode() : async Text { ... };
-    public shared func submitRSVP(name : Text, attending : Bool, inviteCode : Text) : async () { ... };
-    public query ({ caller }) func getAllRSVPs() : async [InviteLinksModule.RSVP] { ... };
-    public query ({ caller }) func getInviteCodes() : async [InviteLinksModule.InviteCode] { ... };
 };
```

### 3. Do not redeclare mixin-provided functions

Lint rules now error if any of these are declared directly in the actor:

- `generateInviteCode`
- `submitRSVP`
- `getAllRSVPs`
- `getInviteCodes`

### 4. Frontend unchanged

Actor method names and signatures are unchanged. No frontend migration is required beyond rebuilding bindings after the backend update.

## Upgrade checklist

- [ ] Bump `caffeineai-invite-links` to `~1.0.0` in `mops.toml`
- [ ] Ensure `caffeineai-authorization ~1.0.0` is installed and `include MixinAuthorization(accessControlState, null)` is present in `main.mo`
- [ ] Add `let inviteState = InviteLinksModule.initState()` and `include MixinInviteLinks(accessControlState, inviteState)` in `main.mo`
- [ ] Remove the four mixin-provided functions from `main.mo` and any custom mixins (keep top-level `InviteLinksModule.initState()`)
- [ ] Run `mops install`, `mops build`, and `mops lint`
- [ ] Regenerate frontend bindings if your workflow requires it
