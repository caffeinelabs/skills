# Migration: v1.x.y -> v2.x.y

## Summary

v2 lifts `@caffeineai/core-infrastructure` onto `@icp-sdk/auth` v9. Sign-in state lives in storage rather than on a singleton `AuthClient`, so every tab of an origin converges: sign in or out in one tab and the others follow. `IdleManager` is gone. The Internet Identity URL and canister id are platform-managed — apps must not pass `identityProvider`.

Apps that only use `login()`, `clear()`, and `isAuthenticated` keep working. Apps that passed `createOptions.identityProvider` or that re-enabled idle handling must drop those options.

## Breaking changes

### 1. Package pins in `package.json`

```diff
-    "@caffeineai/core-infrastructure": "^1.4.0",
-    "@icp-sdk/auth": "^7.1.0",
+    "@caffeineai/core-infrastructure": "^2.0.0",
+    "@icp-sdk/auth": "^9.0.0",
```

`@icp-sdk/core` stays at `^5.3.0`. Auth v10 (core v6) is a later pin bump.

### 2. `identityProvider` is not an app option

Caffeine already injects `II_URL` and `II_CANISTER_ID`. `InternetIdentityProvider` reads those and builds the v9 `{ authorizeUrl, canisterId }` pair (or omits it for mainnet II). Passing `identityProvider` on `createOptions` is a type error and is stripped at runtime.

```diff
-<InternetIdentityProvider
-  createOptions={{ identityProvider: "https://id.ai" }}
->
+<InternetIdentityProvider>
```

### 3. `IdleManager` / `idleOptions` are gone

`createOptions.idleOptions`, `onIdle`, `idleTimeout`, `disableIdle`, and `disableDefaultIdleCallback` no longer exist. The session is bounded at Internet Identity via optional `maxTimeToIdle` and `maxTimeToLive` on `signIn()`. Leaving them unset uses the provider defaults (currently seven days idle and thirty days in total).

`InternetIdentityProvider` no longer disables a client-side idle timer — there is none.

### 4. Session expiry is a distinct hook status

`loginStatus` may be `"expired"` when the session ended (idle, TTL, or provider revoke). That is not a deliberate `clear()`. Gate authenticated UI on `isAuthenticated` as before. Use `isSessionExpired` when the app should say the session ended rather than showing a clean signed-out screen.

Sign-out in another tab sets `loginStatus` back to `"idle"` and `isAuthenticated` to `false`.

## Upgrade checklist

- [ ] Bump `@caffeineai/core-infrastructure` to `^2.0.0` and `@icp-sdk/auth` to `^9.0.0`
- [ ] Remove `identityProvider` from `createOptions` — Caffeine supplies the II deployment
- [ ] Remove `idleOptions` from `createOptions`
- [ ] If the app handled idle logout itself, subscribe to `isSessionExpired` instead
- [ ] Run `pnpm install` and verify the frontend builds without errors
