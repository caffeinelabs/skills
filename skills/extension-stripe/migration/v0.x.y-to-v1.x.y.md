# Migration: v0.x.y -> v1.x.y

## Summary

v1 updates the `caffeineai-stripe` mops package to `1.0.0` and moves all required Stripe actor endpoints into `MixinStripe`. Apps no longer declare `isStripeConfigured`, `setStripeConfiguration`, `createCheckoutSession`, `getStripeSessionStatus`, or `transform` manually in `main.mo` or custom mixins. Lint rules now check for `include MixinStripe(accessControlState, stripeState)` instead of per-function declarations in the actor body. Configuration state is owned at actor top level as `stripeState : Stripe.StripeState` and passed into the mixin.

This is **not** a no-op on stable state. v0 persisted `var configuration : ?Stripe.StripeConfiguration`. v1 replaces that actor field with `stripeState` wrapping the same optional config. Motoko matches actor fields by name and type, so the upgrade needs an explicit `src/backend/migrations/` step or it fails `mops check` / discards Stripe secrets.

Prerequisite: `caffeineai-authorization` `1.0.0` with `include MixinAuthorization(accessControlState, null)` in `main.mo`.

## Breaking changes

### 1. `mops.toml` version bump

```diff
-caffeineai-stripe = "0.1.2"
+caffeineai-stripe = "1.0.0"
```

The package now depends on `caffeineai-authorization` for admin checks inside the mixin.

### 2. Replace manual Stripe endpoints with `MixinStripe`

Remove all hand-written Stripe actor endpoints and the old `var configuration` field. Add the mixin in `main.mo` (not in a custom mixin file).

Under enhanced migration (Caffeine-generated apps), declare the field with a type only — do **not** call `Stripe.initState()` in the actor body (`M0250`). The migration in section 3 supplies the value.

```diff
 import Stripe "mo:caffeineai-stripe/stripe";
 import AccessControl "mo:caffeineai-authorization/access-control";
 import MixinAuthorization "mo:caffeineai-authorization/MixinAuthorization";
-import OutCall "mo:caffeineai-http-outcalls/outcall";
+import MixinStripe "mo:caffeineai-stripe/MixinStripe";
 import Runtime "mo:core/Runtime";

 actor {
     let accessControlState = AccessControl.initState();
     include MixinAuthorization(accessControlState, null);
+    let stripeState : Stripe.StripeState;
+    include MixinStripe(accessControlState, stripeState);

-    var configuration : ?Stripe.StripeConfiguration = null;
-
-    public query func isStripeConfigured() : async Bool { ... };
-    public shared ({ caller }) func setStripeConfiguration(...) : async () { ... };
-    public func getStripeSessionStatus(sessionId : Text) : async Stripe.StripeSessionStatus { ... };
-    public shared ({ caller }) func createCheckoutSession(...) : async Text { ... };
-    public query func transform(input : OutCall.TransformationInput) : async OutCall.TransformationOutput { ... };
 };
```

If Stripe endpoints live in a custom mixin (for example `fees-subjects-transport-timetable-csv-api.mo`), delete them there and add `let stripeState : Stripe.StripeState; include MixinStripe(accessControlState, stripeState)` in `main.mo` instead.

`Stripe.initState()` in [SKILL.md](../SKILL.md) is a state-shape hint for projects without enhanced migration. Do not copy that initializer into an EM actor body.

### 3. Map `configuration` into `stripeState`

`StripeState` is `{ var configuration : ?StripeConfiguration }`. The payload type is unchanged; the actor field is not. Motoko treats this as a **rename plus restructure**:

- remove `configuration`
- add `stripeState`

That requires an explicit migration. A `main.mo` swap alone will fail stable-compatibility checks (`M0170`) or drop the secret key until someone reconfigures Stripe.

Follow [migrating-motoko-actors](../../migrating-motoko-actors/SKILL.md): at most one pending file per build; if this build already added a migration, fold this mapping into that file. Inline old and new types — no project imports, only `mo:core/...`. List **every** stable field in both `OldActor` and `NewActor`; omitting `configuration` from `OldActor` discards it.

`OldActor` is the `NewActor` of the previous file in `src/backend/migrations/` (lex order), or the pre-conversion shape if that is the chain start — never the current `main.mo`. Pass every unchanged field through. The Stripe-specific mapping is:

```motoko
stripeState = { var configuration = old.configuration };
```

Do **not** use `Stripe.initState()` here. That would set `configuration` to `null` and wipe live keys.

Sketch (other fields omitted — copy them from the previous `NewActor`):

```motoko
// src/backend/migrations/YYYYMMDD_HHMMSS.mo
module {
  type StripeConfiguration = {
    secretKey : Text;
    allowedCountries : [Text];
  };
  type StripeState = {
    var configuration : ?StripeConfiguration;
  };

  type OldActor = {
    var configuration : ?StripeConfiguration;
    // every other previously deployed stable field
  };

  type NewActor = {
    stripeState : StripeState;
    // every other stable field, including new actor fields
  };

  public func migration(old : OldActor) : NewActor {
    {
      stripeState = { var configuration = old.configuration };
      // pass through every other field
    };
  };
};
```

Then run `mops check --fix` until it passes, and `mops build` once at the end.

### 4. Do not redeclare mixin-provided functions

Lint rules now error if any of these are declared directly in the actor:

- `isStripeConfigured`
- `setStripeConfiguration`
- `createCheckoutSession`
- `getStripeSessionStatus`
- `transform`

### 5. Frontend unchanged

Actor method names and signatures are unchanged. No frontend migration is required beyond rebuilding bindings after the backend update.

## Upgrade checklist

- [ ] Bump `caffeineai-stripe` to `1.0.0` in `mops.toml`
- [ ] Ensure `caffeineai-authorization` `1.0.0` is installed and `include MixinAuthorization(accessControlState, null)` is present in `main.mo`
- [ ] Add `let stripeState : Stripe.StripeState` and `include MixinStripe(accessControlState, stripeState)` in `main.mo`
- [ ] Remove the five mixin-provided functions and the old `var configuration` declaration from `main.mo` and any custom mixins
- [ ] Add or fold a `src/backend/migrations/` step that sets `stripeState = { var configuration = old.configuration }` and passes through every other stable field
- [ ] Run `mops install`, `mops check --fix`, `mops build`, and `mops lint`
- [ ] Regenerate frontend bindings if your workflow requires it
