# AGENTS.md

Monorepo of agent-readable skill files and their supporting Motoko (backend) and TypeScript/React (frontend) packages for building on the Caffeine AI platform (Internet Computer).

## Layout

- `skills/` — one directory per skill, each containing a `SKILL.md` (Markdown with YAML frontmatter). Some skill dirs also hold `api-reference.md`, `examples.md`, and `references/`. This is documentation, not compiled code.
- `packages/<name>/backend/` — Motoko package built with [mops](https://mops.one), published as `caffeineai-*`.
- `packages/<name>/frontend/` — TypeScript/React package built with `tsc`, published as `@caffeineai/*`.
- `packages/<name>/backend/rules/` — `*.toml` lintoko rule definitions (tree-sitter queries), not source code.

## Backend (Motoko) packages

Each `packages/*/backend/` has a `mops.toml` and is built/tested with the [mops CLI](https://mops.one) (run inside the package's `backend/` dir). Tests are Motoko files named `*.test.mo` (see `packages/oql/backend/test/`).

The `moc` (Motoko compiler) version is pinned per package under `[toolchain]` in `mops.toml`; it is not uniform across packages (values include `1.2.0`, `1.7.0`, `1.9.0`). Respect each package's pin. `packages/oql` also pins `pocket-ic`, and `packages/caffeine-lints` pins `lintoko`.

Committed `mops.lock` files are generated by mops — do not hand-edit them.

## Frontend (TypeScript) packages

Frontend packages live in `packages/{camera,core-infrastructure,object-storage,qr-code}/frontend/`. Verified `package.json` scripts (run inside the package dir):

- `build` — `tsc`
- `type-check` — `tsc --noEmit`
- `clean` — `rimraf dist`
- `biome:check` — `biome check --error-on-warnings .` (lint + format check; treats warnings as errors)
- `biome:check:fix` — `biome check --write --error-on-warnings .`
- `test` — only in `object-storage`: `node --import tsx --test src/**/*.test.ts`

Gotchas:

- Each frontend `tsconfig.json` extends `../../../tsconfig.base.json` (repository root). That base file is not present in this checkout, so `tsc` will not run until it is provided.
- Frontend packages declare workspace deps via `workspace:*` and are meant to be built inside a package-manager workspace; no workspace manifest is committed here.
- `dist/` is a build output — never hand-edit it.

## Conventions

- License is Apache-2.0.
- There is no CI configuration and no root-level build manifest in this repository; commands run per package.
- `SKILL.md` frontmatter declares exact `mops`/`npm` package versions in a `compatibility:` block; keep it in sync with the versions the skill documents.
