# AGENTS.md

Monorepo of agent-readable `SKILL.md` files and the reusable Motoko/TypeScript packages they document, for building apps on the Caffeine AI (Internet Computer / Motoko).

## Layout

- `skills/` — one directory per skill, each a self-contained `SKILL.md` with YAML frontmatter. `extension-*` document packages in `packages/`; `connector-*` document external-service integrations; the rest (`writing-motoko`, `reviewing-motoko`, `migrating-*`, `mops-cli`, `troubleshooting-*`) are reference guides.
- `packages/<name>/backend/` — a Motoko package (`mops.toml`), published to the mops registry as `caffeineai-*`.
- `packages/<name>/frontend/` — a TypeScript package (`package.json`), published as `@caffeineai/*`.

## Build, test, lint, format

There is no repo-root build system; run commands inside the relevant package directory.

Frontend (`packages/*/frontend`, npm scripts):

- Build: `npm run build` (`tsc`)
- Type-check: `npm run type-check` (`tsc --noEmit`)
- Lint/format check: `npm run biome:check` (fails on warnings)
- Lint/format fix: `npm run biome:check:fix`
- Test (only `core-infrastructure` and `object-storage` define it): `npm test`

Backend (`packages/*/backend`, [mops](https://mops.one)):

- Test (packages with a `test` dev-dependency and a `test/` dir, e.g. `oql`, `email`, `email-marketing`, `http-endpoints`): `mops test`

## Conventions and gotchas

- `moc` (and sometimes `mo-fmt`, `lintoko`, `pocket-ic`) are pinned per package under `[toolchain]` in each `mops.toml`; versions differ between packages (e.g. `oql` uses `moc = "1.14.0"`).
- `packages/*/frontend/dist/` is generated by `tsc` — never hand-edit it. `clean` removes it (`rimraf dist`).
- `packages/*/backend/rules/*.toml` are lintoko rules consumed by `caffeineai-lints`; a key rule forbids importing `mo:base` (use `mo:core/*` instead).
- Frontend packages reference each other with `workspace:*`; builds assume the sibling packages are present.
- Each `SKILL.md` begins with YAML frontmatter (`name`, `description`, `version`, `compatibility`) whose `compatibility` versions must match the documented package versions.
