# AGENTS.md

Monorepo of agent-readable skill files and the Motoko/TypeScript packages they document for building on the Caffeine AI platform.

## Layout

- `skills/` — one directory per skill, each a self-contained `SKILL.md` with YAML frontmatter (`name`, `description`, `version`, `compatibility`). Directories are prefixed `extension-*` (platform components), `connector-*` (third-party integrations), plus standalone Motoko guides (e.g. `writing-motoko`, `reviewing-motoko`, `mops-cli`).
- `packages/` — reusable packages referenced by skills. Each has up to two sub-packages:
  - `backend/` — a Motoko package managed by [mops](https://mops.one), published as `caffeineai-*`.
  - `frontend/` — a TypeScript/React package, published as `@caffeineai/*`.

There is no root build system, Makefile, or CI workflow; each package is built and tested on its own from inside its directory.

## Backend packages (Motoko / mops)

Run from a package's `backend/` directory (needs the `mops` CLI, v3.x):

- Type-check: `mops check`
- Build: `mops build`
- Test: `mops test` (test files live in `test/*.test.mo`)

Conventions:

- `moc` is pinned per package under `[toolchain]` in `mops.toml`; use exactly that version. Some packages also pin `pocket-ic` and `lintoko`.
- `mops.lock` is generated — do not hand-edit it.
- Do not import `mo:base` (deprecated); use `mo:core` equivalents (e.g. `import Array "mo:core/Array"`). This is enforced by the `no-base-import` rule in `packages/caffeine-lints`.
- mops does not use or invoke `dfx`.

## Frontend packages (TypeScript / React)

Run from a package's `frontend/` directory:

- Build: `npm run build` (runs `tsc`)
- Type-check: `npm run type-check` (`tsc --noEmit`)
- Lint/format: `npm run biome:check` (Biome; fails on warnings). Auto-fix with `npm run biome:check:fix`.
- Clean: `npm run clean`
- Test (only in packages that define it, e.g. `core-infrastructure`, `object-storage`): `npm run test`

Conventions:

- `dist/` is generated by `tsc` — never hand-edit it.
- Packages reference each other with `workspace:*`; install with a workspace-aware client (`pnpm`).
- Each `frontend/tsconfig.json` extends a shared `tsconfig.base.json` at the repo root.
