# AGENTS.md

Agent-readable skill files and the packages they document, for building apps on the Caffeine AI / Internet Computer platform.

## Layout

- `skills/` — self-contained `SKILL.md` docs (plus optional supporting `.md` files). `extension-*` and `connector-*` document packages; others (e.g. `writing-motoko`, `reviewing-motoko`) are language/workflow guides.
- `packages/` — the publishable code the skills document. Each package has `backend/` (Motoko, published to the mops registry as `caffeineai-*`) and/or `frontend/` (TypeScript, published to GitHub Packages as `@caffeineai/*`).

## Working on a frontend package

Run commands from the individual package's `frontend/` directory. Verified `package.json` scripts (not every package defines all of them):

- `build` — `tsc`
- `type-check` — `tsc --noEmit`
- `biome:check` — lint/format check, fails on warnings
- `biome:check:fix` — apply lint/format fixes
- `test` — `node --import tsx --test src/**/*.test.ts` (only in packages that define it)

Each `frontend/tsconfig.json` extends `../../../tsconfig.base.json`. That base config and the workspace root (lockfile, root `package.json`) are not part of this checkout; frontend packages reference workspace siblings via `workspace:*` and expect the Node/pnpm workspace to supply them. Do not add a root build config.

## Working on a backend package

Backends are Motoko managed with mops (`mops.toml`, `mops.lock`). The pinned Motoko compiler is declared per package under `[toolchain] moc = "..."`; versions differ between packages, so honor each package's pin.

## Conventions and gotchas

- `backend/*/rules/*.toml` are lintoko rules (tree-sitter queries), not build config. Honor them when editing Motoko:
  - Do not import `mo:base` (deprecated); use the `mo:core` equivalent.
  - Migration files under `src/backend/migrations/*.mo` must be self-contained — inline types/values instead of using relative imports, or the migration chain breaks.
- Keep each `SKILL.md`'s YAML frontmatter accurate: `name`, `description`, `version`, and `compatibility` (the exact mops/npm/toolchain versions the skill documents). The documented versions must match the package they describe.
- `frontend/dist/` is generated by `tsc`; never hand-edit it.
