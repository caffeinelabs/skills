# AGENTS.md

Monorepo of agent-readable skill files and the reusable Motoko/TypeScript packages they document, for building Caffeine AI extensions on the Internet Computer (ICP).

## Layout

- `skills/` — one directory per skill, each a self-contained `SKILL.md` with YAML frontmatter (`name`, `description`, `version`, `compatibility`). `extension-*` document packages; `connector-*` document external-service connectors; the rest (`writing-motoko`, `reviewing-motoko`, `mops-cli`, `migrating-motoko-actors`, ...) are general guidance.
- `packages/<name>/backend/` — Motoko library package published to the mops registry as `caffeineai-*` (`mops.toml`).
- `packages/<name>/frontend/` — TypeScript package published as `@caffeineai/*` (`package.json`).

## Backend (Motoko / mops)

All backend packages are mops libraries (no `[canisters]` block). Requires the `mops` CLI (3.x); `moc` and, where present, `lintoko`/`pocket-ic` versions are pinned per package in `mops.toml` `[toolchain]` — do not override them. Run from a package's `backend/` directory:

- Type-check: `mops check src/**/*.mo` (library packages pass file paths, not canister names).
- Test: `mops test` (currently only `packages/oql/backend` has a `test/` suite). Use `mops test --mode wasi` for tests needing `to_candid`/`from_candid`.
- CI-safe install-free run: append `--locked` (requires an up-to-date `mops.lock`).

Use `mo:core`, never `mo:base` — the `no-base-import` lintoko rule in `packages/caffeine-lints` warns on `mo:base` imports. Migration files (`**/src/backend/migrations/*.mo`) must not import local modules (`migration-self-contained` rule).

## Frontend (TypeScript)

Per-package `package.json` scripts (run in the package's `frontend/` directory):

- `build` — `tsc`
- `type-check` — `tsc --noEmit`
- `biome:check` / `biome:check:fix` — Biome lint/format; `--error-on-warnings` means warnings fail the check.
- `test` — where present, `node`'s built-in test runner over `src/**/*.test.ts`.

Frontend `tsconfig.json` files extend a repo-root `tsconfig.base.json` and the packages expect Biome and a workspace-level dependency setup that are not part of this checkout, so `build`/`biome`/`type-check` require that surrounding tooling to be present.

## Conventions

- `skills/mops-cli/SKILL.md` is vendored from an upstream repository and regenerated by a sync script (see the "Do not edit below this comment" marker); edit it upstream, not here.
- `packages/*/frontend/dist/` and `*.tgz` are build/publish artifacts, not source.
